# Dashboard динамики качества (PLAN §19.3, этап 5.2)

Решения владельца 2026-11-15: **1а, 2а, 3а, 4а + Recharts v3** (дополнительно к варианту «свой SVG»:
библиотеку ставим вместо ручной отрисовки).

## Решения

| № | Вопрос | Решение |
| --- | --- | --- |
| 1 | Источник данных | **(а)** читать report-JSON на запросе; миграции нет, артефакт остаётся источником правды |
| 2 | Объём первого среза | **(а)** тренд по severity, новые/закрытые, стоимость и длительность, фильтр по категориям; динамика производительности — отдельным шагом |
| 3 | Точка на шкале | **(а)** прогон по хосту; несопоставимые пары помечаются, покрытие пишется рядом |
| 4 | Где страница | **(а)** `/sites/[host]/dashboard`, графики — Recharts v3 |

## Что читается и откуда

- **Находки, severity, категории, scores, покрытие** — из сохранённого отчёта (`report_key` →
  `read_artifact`). Таблица `findings` содержит дубли, снятые chief-слоем, поэтому SQL-счёт по
  категориям был бы больше отчёта (`api/app/api/main.py::stored_report_summary` уже говорит это про
  `findings_total`).
- **Токены, вызовы и стоимость** — из строки `audits`: это то, что прогон потратил, включая попытку,
  которая упала и была повторена. Стоимость остаётся оценкой (`null`, если модель не в прайсе).
- **Новые/закрытые/оставшиеся** — `compare_reports` между соседними прогонами с отчётами, с его же
  вердиктом сопоставимости. Несопоставимая пара не получает чисел, а получает причину.
- **Неизмеренное** — `null`, никогда `0`: упавший прогон, отсутствующий артефакт, неоценённая
  стоимость.

## Контракт API

`GET /sites/{host}/history?limit=30` (`ge=1, le=200`) — только page-аудиты (`scope != "sitemap"`),
старые первыми:

```
{ "host": "localhost:8081",
  "runs": [ { "audit_id", "started_at", "finished_at", "status", "agent_version",
              "pages_audited", "findings_total", "by_severity", "by_category", "scores",
              "duration_ms", "tokens_in", "tokens_out", "llm_calls", "cost_estimate_usd",
              "compared_to", "comparable", "comparison_notes", "new", "closed", "remaining" } ],
  "notes": [ … ] }
```

404 — у хоста нет ни одного page-прогона, как у `/sites/{host}`.

## Шаги

1. `api/app/storage/repo.py::page_audits` — все page-аудиты, старые первыми.
2. `api/app/dashboard.py` — `RunPoint`, `SiteHistory`, `read_reports`, `category_counts`,
   `build_history`; дельты через `compare_reports`, `null` для неизмеренного.
3. `api/app/api/main.py` — `GET /sites/{host}/history`, фильтр хоста через существующий `site_host`,
   окно `limit` берётся по последним прогонам, ответ строится из отчётов.
4. `web/app/lib/audits.ts` — тип `SiteHistory` и `getSiteHistory(host)`.
5. `web/app/sites/[host]/dashboard/page.tsx` — серверная страница: сводка, графики, таблица прогонов,
   ссылки на отчёты.
6. `web/app/components/history-charts.tsx` — клиентский компонент на Recharts v3: стек по severity,
   новые/закрытые, категории с фильтром, стоимость.
7. Ссылка «Dashboard» со страницы хоста; `?category=` на странице отчёта, чтобы «перейти к находкам»
   вело к отфильтрованному списку.
8. Тесты: юнит на `build_history` (нет отчёта → `null`; несопоставимая пара → дельт нет; категории
   считаются по отчёту; стоимость `null` не превращается в 0), интеграционный на endpoint поверх
   реального прогона фикстуры; web — `bun run build`, `tsc`, biome. Страница проверена реальным
   браузером на живом стеке (4 графика, 30 строк, фильтр категории в отчёте); расширение
   CI-скриншот-джобы на дашборд — отдельным изменением.

## Чего этот шаг не делает

- Не меняет детекцию: `agent_version` не двигается (dashboard не входит в хеш), прогоны корпуса
  перезапускать не нужно.
- Не хранит снимок в БД (решение 1а), не добавляет динамику производительности (решение 2а), не
  вводит верхнеуровневый `/dashboard` по всем хостам.
